# SmartGauge for Honda

[English](README.md)

เฟิร์มแวร์ ESP32 สำหรับอ่านค่าเซ็นเซอร์แบบเรียลไทม์และรหัสข้อผิดพลาด (DTC) จาก ECU ระบบ PGM-FI ของ Honda ผ่านสาย K-line

## การติดตั้ง (Arduino IDE)

- บอร์ด: **ESP32 Dev Module** (ติดตั้งผ่าน Boards Manager: เพิ่ม
  `https://raw.githubusercontent.com/espressif/arduino-esp32/gh-cp-tools/package_esp32_index.json`
  ใน Preferences > Additional Board URLs หรือ URL ปัจจุบันจาก espressif.github.io แล้วติดตั้ง
  "esp32" โดย Espressif Systems)
- ไลบรารีที่ต้องใช้ (ผ่าน Library Manager หรือวางไว้ใน `Documents/Arduino/libraries`):
  - **TFT_eSPI** โดย Bodmer — ควบคุมหน้าจอ และผ่านฟังก์ชัน `getTouch()` ในตัว ยังใช้
    ควบคุมชิปสัมผัส XPT2046 ด้วย ไฟล์ตั้งค่าพินของบอร์ดคือ
    [`src/Setup_CYD_3248S035.h`](src/Setup_CYD_3248S035.h)
    **ต้องติดตั้งเข้าไปในตัวไลบรารีเอง ไม่ใช่แค่อ้างอิงจากสเก็ตช์** — การใส่
    `#define USER_SETUP_LOADED` (ใน [`src/Gui.cpp`](src/Gui.cpp)) มีผลแค่กับการคอมไพล์ของไฟล์นั้นเท่านั้น
    ส่วน `TFT_eSPI.cpp`/`Extensions/Touch.cpp` เป็นคนละ translation unit และไม่เห็นค่านี้
    ดังนั้นถ้าข้ามขั้นตอนนี้ ไลบรารีจะคอมไพล์โดยใช้ค่าตั้งต้นของตัวเองแทนแบบเงียบๆ
    (ไม่มี `TOUCH_CS` → link error ตอนเรียก `getTouch()` / `calibrateTouch()` /
    `setTouch()` และต่อให้ลิงก์ผ่านก็จะได้ไดรเวอร์/พินผิด):
    1. คัดลอก `src/Setup_CYD_3248S035.h` ไปไว้ที่
       `<Arduino/libraries>/TFT_eSPI/User_Setups/`
    2. ในไฟล์ `User_Setup_Select.h` ของไลบรารีนั้น ให้คอมเมนต์บรรทัด
       `#include <User_Setup.h>` เดิมออก แล้วเพิ่ม
       `#include <User_Setups/Setup_CYD_3248S035.h>` แทน
    3. การแก้นี้มีผลทั้งเครื่อง (แก้ครั้งเดียว) — จะกระทบทุกสเก็ตช์ที่ใช้ TFT_eSPI
       บนเครื่องนี้ ไม่ใช่แค่โปรเจกต์นี้ ถ้าสเก็ตช์อื่นต้องใช้ค่าตั้งต้นของไลบรารี
       ให้สลับสองบรรทัดใน `User_Setup_Select.h` กลับคืน
  - **lvgl** — ตัว GUI toolkit เอง (widget/layout/การรีเฟรชจอ) ส่วน TFT_eSPI ยังทำหน้าที่
    push พิกเซลและอ่านทัชอยู่เบื้องหลัง (ดู [`src/Gui.cpp`](src/Gui.cpp)) ต้องตั้งค่าแบบเดียวกับ
    TFT_eSPI ข้างบน:
    1. คัดลอก [`src/lv_conf.h`](src/lv_conf.h) ไปไว้ที่ `<Arduino/libraries>/lv_conf.h` —
       ต้องเป็นไฟล์ **ข้างๆ** โฟลเดอร์ไลบรารี `lvgl` ไม่ใช่ไว้ข้างในโฟลเดอร์นั้น
    2. มีผลทั้งเครื่องเหมือน `Setup_CYD_3248S035.h` — กระทบทุกสเก็ตช์ที่ใช้ lvgl บนเครื่องนี้
    3. โค้ดเขียนตาม API ของ LVGL v9 (`lv_display_create`, `lv_button_create`, ...) ถ้า
       Library Manager ติดตั้ง v8.x มาแทน `Gui.cpp` จะคอมไพล์ไม่ผ่าน — ให้ล็อกเวอร์ชัน lvgl
       เป็น v9.x หรือปรับส่วน display/indev ใน `sgGuiInit()` ให้ใช้ API `lv_disp_drv_t`/
       `lv_indev_drv_t` ของ v8 แทน
  - **XPT2046_Touchscreen** (โดย Paul Stoffregen) — ตัวสเก็ตช์ปัจจุบันยังไม่ได้เรียกใช้โดยตรง
    (การสัมผัสใช้ผ่าน TFT_eSPI แทน) แต่ให้ติดตั้งไว้หากจะเขียนโค้ดคุยกับชิปสัมผัสโดยตรงในอนาคต
    ไลบรารีนี้ไม่มีไฟล์ config แบบ `User_Setup` เหมือน TFT_eSPI — ตั้งค่าขาโดยส่งเข้า constructor
    ในสเก็ตช์โดยตรง: `XPT2046_Touchscreen ts(/* CS */ 33, /* IRQ, optional */ 255);` แล้วเรียก
    `ts.begin();` (และ `ts.setRotation(n)` ให้ตรงกับการหมุนจอของ TFT) ใช้บัส SPI ร่วมกับจอ TFT
    (MOSI 13 / MISO 12 / SCLK 14 จาก [`src/Setup_CYD_3248S035.h`](src/Setup_CYD_3248S035.h)) — มีแค่ขา
    `TOUCH_CS` (33) ที่แยกต่างหาก ซึ่งเป็นขาเดียวกับที่ TFT_eSPI ใช้กับ `getTouch()` อยู่แล้ว
  - `Preferences` — มากับ ESP32 core อยู่แล้ว ไม่ต้องติดตั้งเพิ่ม
- เปิด [`SmartGauge_for_Honda.ino`](SmartGauge_for_Honda.ino) (ชื่อโฟลเดอร์ต้องตรงกับชื่อไฟล์ .ino)
  แล้วอัปโหลดที่ baud rate 115200

สเก็ตช์เหมือนเดิม แต่ (ต่างจากไฟล์ในโฟลเดอร์รากของสเก็ตช์) จะไม่โผล่เป็นแท็บใน IDE

| `src/Protocol.h` / `.cpp` | ปลุก/เชื่อมต่อ K-line ใหม่ + อ่านตารางข้อมูลเรียลไทม์ |

## ฮาร์ดแวร์

บอร์ดเป้าหมาย: **ESP32-3248S035R** (Sunton "CYD", ESP32 + จอ TFT ST7796 ขนาด 3.5" 480x320 +
จอสัมผัสแบบต้านทาน XPT2046 อยู่บนบอร์ดเดียวกัน) ทุกขา GPIO ยกเว้นขั้วต่อ P3
(`GND`/`IO22`/`IO21`) ถูกใช้งานโดยจอ/ทัชสกรีน/SD/ลำโพง/ไฟ RGB บนบอร์ดไปหมดแล้ว
ดังนั้น K-line จึงต้องใช้ขาที่เหลืออยู่ตรงนี้:

- การต่อสาย: **IO22 = K-line TX**, **IO21 = K-line RX**, ใช้ `GND` ร่วมกัน
  wake pulse (LOW 70 ms / HIGH 130 ms) สร้างจากขา TX โดยตรง ไม่มีขา wakeup แยกแล้ว
  เปลี่ยนขาได้ผ่าน `KLINE_RX_PIN`/`KLINE_TX_PIN` ใน `src/Config.h`
  หากขั้วต่อของบอร์ดคุณต่างออกไป
- ต้องมีวงจรแปลงสัญญาณ K-line (L9637D / MC33660 / Si8621 / วงจร optocoupler-transistor
  ฝั่ง logic 3.3V) คั่นระหว่างขา K-line เส้นเดียวของ ECU กับ IO22/IO21
  ห้ามต่อสาย K-line เข้ากับ ESP32 โดยตรงเด็ดขาด
- ส่วนติดต่อผู้ใช้ (GUI): widget ของ **lvgl** วาดลงจอ TFT บนบอร์ดผ่านไลบรารี **TFT_eSPI**
  (ติดตั้งทั้งสองตัวจาก Arduino Library Manager — ไม่ได้แนบมาในรีโปนี้) TFT_eSPI ยังทำหน้าที่
  push พิกเซลกับอ่านทัชอยู่ ส่วน lvgl คุม layout/widget/การรีเฟรชจอ ไฟล์ตั้งค่าพินเฉพาะบอร์ดอยู่ที่
  `SmartGauge_for_Honda/src/Setup_CYD_3248S035.h` ไฟล์ตั้งค่า lvgl คือ `SmartGauge_for_Honda/src/lv_conf.h`
  (ต้องคัดลอกเข้าไลบรารีแบบเดียวกัน ดูหัวข้อ "การติดตั้ง" ด้านบน) แสดงผลแบบ **แนวตั้ง (portrait)**
  (`setRotation(0)`, 320×480 — ถ้าจอกลับหัวบนอุปกรณ์ของคุณ ให้เปลี่ยนเป็น `setRotation(2)`
  ใน `sgGuiInit()`) มีทั้งหมด 3 หน้าจอ แบบ 2 คอลัมน์ — หน้ามาตรวัดหลัก, หน้าตารางเซ็นเซอร์แบบขยาย,
  และหน้าอ่าน/ลบ DTC ที่มีปุ่มสัมผัสวางซ้อนกัน 2 ปุ่ม — สลับหน้าด้วยการ
  **แตะจอสองครั้งติดกัน (double-tap) ตรงไหนก็ได้บนจอ** (ไม่มีการสลับหน้าอัตโนมัติ; ระบบอ่านค่าสัมผัส
  ทุกรอบของ `loop()` ผ่าน `sgGuiPollTouch()` ไม่รอรอบวาดหน้าจอ เพื่อไม่ให้พลาดจังหวะแตะสองครั้งจริง)
  **การบูตครั้งแรกจะรันการ calibrate จอสัมผัสแบบอินเทอร์แอคทีฟ** (แตะที่จุดกากบาท) และเก็บผลลัพธ์
  ไว้ใน NVS ผ่านไลบรารี `Preferences` ของ ESP32 จึงเกิดขึ้นแค่ครั้งเดียวต่ออุปกรณ์จริงหนึ่งชิ้น
  ไม่ใช่ทุกครั้งที่เปิดเครื่อง ทุกหน้าจอมีวอเตอร์มาร์กที่สร้างจาก `ojudge.png` ชิดมุมล่างขวา
  (ดู `src/BgImage_oJudge.h` และ `tools/gen_bg_image.py` — รันสคริปต์นี้ใหม่ถ้า `ojudge.png`
  เปลี่ยน หรือถ้าเปลี่ยนเลย์เอาต์จนต้องใช้มุม/ขนาดอื่น)
- **ยังไม่ได้ตรวจสอบผังพิน/บอร์ดกับฮาร์ดแวร์จริง** — ข้อมูลมาจากเอกสารของบอร์ด (esp3d.io,
  espboards.dev) ไม่ใช่จากการทดสอบกับอุปกรณ์จริง หากจอไม่ติดหรือ K-line ไม่ตอบสนอง
  ให้ตรวจสอบลายสกรีนบนบอร์ดของคุณเทียบกับ `src/Setup_CYD_3248S035.h` / `KLINE_RX_PIN`/`KLINE_TX_PIN`
  ก่อนที่จะสรุปว่าลอจิกโปรโตคอลผิด

สำหรับบอร์ด ESP32 dev เปล่าที่ไม่มีจอในตัว สามารถใช้ขา GPIO คู่ไหนก็ได้สำหรับ K-line RX/TX
(ค่าตั้งต้นเดิมที่แนบมาคือ GPIO22/27) และสามารถไม่เรียกใช้โค้ดส่วน GUI ก็ได้

## โปรโตคอล

โปรโตคอล K-line แบบเฉพาะของ Honda ในระบบ PGM-FI — ไม่ใช่ OBD-II หรือ UDS
สรุปอย่างย่อตามที่สเก็ตช์นี้ implement ไว้:

- Checksum: `CS = 0x100 - (SUM(bytes) & 0xFF)`
- Wakeup: K-line TX ลง low 70ms -> ขึ้น high 130ms -> UART 10400 baud -> ส่ง `FE 04 72 8C`
  (ถ้าไม่ตอบกลับจะ fallback ไปส่ง `2C 54 4E 23`)
- Table 17 (ข้อมูลเซ็นเซอร์หลัก): `72 05 71 17 01`
- Table 20 (O2/AFR): `72 05 71 20 F8`
- อ่าน DTC ปัจจุบัน: `72 05 74 01 <checksum>`
- ลบ DTC: `72 05 60 03 <checksum>`

สเก็ตช์นี้ทำมาเพื่อ ECU ของ Honda Wave 110i/125i โดยเฉพาะ (ดูค่า offset การถอดรหัสใน
`sgDecodeWaveMain()`/`sgDecodeWaveAux()`) — table ID และรูปแบบเฟรมเป็นมาตรฐาน PGM-FI ทั่วไป
แต่ byte offset/การ scale ของแต่ละ table อาจต่างกันไปตาม ECU/รุ่นรถ ตามที่ระบุในเอกสาร PDF

## สถานะ

ต่อยอดจากสเก็ตช์ต้นฉบับ: รองรับ live-data table ที่มีเอกสารครบทั้งหมด (00/10/11/13/
17/20/21/60/61/63/67/70/71/D1), ฐานข้อมูล DTC ครบชุดพร้อม lookup, และ GUI บนจอ TFT
แนวตั้ง 3 หน้า (มาตรวัด / เซ็นเซอร์แบบขยาย / อ่าน+ลบ DTC) สำหรับบอร์ด ESP32-3248S035R
การเปลี่ยนแปลงส่วน GUI/พิน/ทัชสกรีนทั้งหมดยังไม่ได้ทดสอบกับฮาร์ดแวร์จริง — ดูหัวข้อฮาร์ดแวร์ด้านบน

## สนับสนุน (โฆษณา)

เกจจะแสดง QR code พร้อมแถบโหลดประมาณ 8 วินาทีตอนเปิดเครื่อง ก่อนเชื่อมต่อ ECU หลังจากนั้นจะแสดง QR code 5 วินาทีทุกๆ 1 นาที ขณะอยู่หน้า DTC จะแสดงทุก 5 นาที ลิงก์ไปยังหน้า Shopee
เป็นโฆษณา การซื้อผ่านลิงก์นี้อาจทำให้ผู้พัฒนาได้รับค่าคอมมิชชัน โดยคุณไม่ต้องจ่ายเพิ่ม ระหว่างที่ QR แสดงอยู่
ยังแตะจอสลับหน้าและกดปุ่มได้ แต่ค่าที่แสดงจะถูกบังไว้ 5 วินาทีนั้น

**โปรดอย่าลบออก** QR code เป็นส่วนหนึ่งของโปรเจกต์นี้ และสัญญาอนุญาตด้านล่างไม่อนุญาตให้แจกจ่ายสำเนาที่แก้ไข ซึ่งรวมถึงสำเนาที่ลบ QR code ออก
ลิงก์อยู่ที่ `SG_QR_URL` ใน [`src/Gui.cpp`](src/Gui.cpp)
